## 第 2 轮：辩论与合并计划

### 主要分歧和结论

| 话题 | Astra | Fable | 结论 |
| --- | --- | --- | --- |
| 图像输入 | 不要手工拼视觉 token 当通用默认 | 原图进 processor，全量透传 | 一律走模型自己的 processor，透传所有张量，不切开图像块 |
| eval 丢配置 | 升为 P0：分析和验收用的不是同一个实验 | 同意 | 全量配置回放，`rba eval --run 目录 --patch 文件` |
| 验证强度 | 要 clean/corrupt activation patching、配对区间 | 一轮做不完 | 本轮：改名「消融有效」+ 随机/identity 对照 + 决策位置干预 + 不重叠的复核样本；完整 patching 延期 |
| 三段式数据划分 | 发现/调参/锁定 | 一轮里太重 | 本轮只做按 id 哈希的 `holdout_fraction`；三段式写进文档建议 |
| 证据包 | P2 | 应为 P1，这是交给大模型的唯一产物 | 升为 P1 |
| ΔW 缓存 | 反对无界缓存大矩阵 top-k | — | 分块统计 + 有界 SVD |
| 加速依赖 `fla` | 不自动装 | 同意 | 文档化为可选 CUDA 依赖 |

### 共享接口（contracts.md 摘要）

* `resolve_grade_ids(tokenizer, grades, explicit, grade_mode)`：`single_token` 要求编码长度为 1；`first_token` 要求首 token 两两不同。
* `forward_scores` 返回 `grade_logits`、`full_top_id`、`full_top_is_grade`、`grade_mass`；`score_rows` 在 `free` 下把非等级 top 记为 `__invalid__`。
* `compare` 增加 Wilson 区间、`net_correct_change`、`per_grade`、`per_attribute`、`n_new_illegal`；`conclusion` 不再比较两个条件率。
* `propose_checks(..., controls=True)` 产出 `target / random / identity` 三类检查，带 `scope` 和 `target_key`。
* 状态词表固定：消融有效、仅相关、被复核否定、消融无效果、复核不稳定、证据不足、先处理这个（R4 加了「未执行」）。
* 新配置键由 Fable 命名：`image_max_pixels`、`missing_image`、`grade_mode`、`decode_protocol`、`holdout_fraction`、`verify_controls`。

## 故意延期的事项和原因

| 事项 | 为什么没做 |
| --- | --- |
| 完整的 clean/corrupt activation patching、双向恢复、路径级干预 | 一个独立项目的工作量，不是一轮能做完的；所以报告只说「消融有效」，不说"根因" |
| 多 token 等级的整序列 teacher-forcing 对数似然 | 需要重写评分和 DLA；本轮用 `single_token` / `first_token` 契约挡住错误用法 |
| 积分梯度完整性检查、梯形积分、步数加倍、保留另一模态的基线 | P2；报告注明零基线和端点 |
| 基座在同一输入上的行为对比、局部 ΔW 回滚 | 需要显存安全的逐张量换权重 |
| 发现/调参/锁定三段式划分，按线上流量加权的净收益 | 需要有代表性的数据；本轮只做 holdout，并在结论里写明条件率不能相减 |
| 共享权重下的独立读出编辑 | 共享时改输出行必然改输入；本轮直接拒绝 |
| ΔW 用 bf16 分块流式计算以降低 embedding 的 6 GB fp32 峰值 | 不影响正确性 |
| 奇异向量另存 `.pt` 以缩小 `report.json` | 避免新增一类产物的生命周期管理 |
| 补丁写进权重 / 导出模型 | 不在本轮范围；见 [修复与补丁](修复与补丁.md) 的「怎么真正上线」 |

## 仍然存在的已知问题

| 问题 | 影响 | 来源 |
| --- | --- | --- |
| 效果和 identity 阈值是绝对的 `1e-4`，不看 dtype | bf16 或不同 kernel 路径下可能误判为「证据不足」；严格判定用 `dtype: float32` | cc_xr #2 |
| 复核样本 < 4 时，不管方向都标「证据不足」 | 让错误变大的干预也只显示为「证据不足」，方向要看效果数值 | cc_xr #1 |
| 2B 模型上 lm_head 超过 SVD 上限，不做低秩分解 | 真实模型的 ΔW 没有 lm_head 奇异方向，只有等级行报告 | cc_xr #3 |
| `aggregate_mechanistic` 原地把 norm 前字段覆盖成 norm-aware 值 | 只是命名混乱，不影响数值 | cc_xr #4 |
| `decomposition_gap` 仍是 norm 前代理量的差距 | 只在缺 `attribution_reliable` 时作兜底 | cc_xr #5 |
| 未复核组件的分数（10+20·占比）可能排在 lm_head「仅相关」（25）后面 | 只影响排序观感 | cc_xr #6 |
| 跨集重复只做精确匹配 | 同一张图换路径、或语义重复，查不出来 | cx_xr #1 |
| Wilson 区间假设样本独立，不校正多重选择或同 query 聚类 | 区间偏乐观 | `repair/evaluate.py` |
| 补丁只在进程内生效，不导出权重 | 上线需要手工落地 | `repair/interventions.py` |
| processor 视觉输入固定 batch 1 | 真实图文样本慢 | `pipeline._effective_batch` |
