# 可视化报告 report.html 怎么读

`rba analyze`（以及 `rba demo`）结束时会在输出目录写一份 **`report.html`**：单个文件、离线可用（脚本、样式、图表、图片缩略图都内嵌在文件里，没有任何外部链接），双击用浏览器打开即可，也可以直接发给同事。

同目录还有：

| 文件 | 是什么 |
| --- | --- |
| `report.html` | 本文介绍的可视化报告 |
| `report_detail.html` / `report.md` | 全文版：全部证据表、提示词、方法说明和状态表 |
| `report.json` | 机器可读的完整结果 |
| `cache/*.json` | 各分析阶段的中间结果，可视化报告就是从这里读数 |
| `eval/eval.json`、`eval/eval_report.html` | 跑过 `rba eval --run 本目录` 后才有 |

## 生成与重新生成

```bash
rba demo                      # 内置小模型，产出 runs/demo/report.html
rba analyze ... --output-dir runs/xxx
rba report runs/xxx           # 从已有目录重新生成 report.html，不加载模型、不重算
rba report runs/xxx --language en
```

`rba report` 只读 `report.json`、`cache/`、`patches/`、`eval/` 里已有的数据，所以几秒就完成。旧版本跑出的目录只要有 `report.json` 也能生成（缺少的部分会显示为空或「—」）。

`rba eval --run runs/xxx --patch ...` 结束后会自动重新生成 `runs/xxx/report.html`，把修复率 / 回退率填进第 5 节；同时在 `runs/xxx/eval/eval_report.html` 写一页单独的验收图。

语言：跟随配置项 `language`（默认 `zh`）。`en` 时标题、说明和结论改成英文。

## 版面

页面顶部是固定导航条：1 总览、2 逐条坏例、3 组件定位、4 微调改了什么、5 补丁、6 文字结论。每张图下方有一段蓝色的 **「怎么看」**（一句话说明这张图怎么读），每节有一段黄色的 **「结论」**（根据数据自动生成的大白话）。

图上的格子、柱子、圆点都可以把鼠标停上去，看精确数值。

## 1. 总览

**数字卡片**：坏例数、当前仍判错的条数、坏例准确率、平均绝对误差（等级差的平均）、对照样本数、非法输出数（`decode_protocol: free` 时输出不是等级词的条数）。

**混淆矩阵热力图**：行是金标，列是模型预测，格子里是条数，越深越多。对角线上的是「坏例里其实已经判对」的；对角线外最深的格子就是最主要的错误类型。

**怎么读：** 先找最深的非对角格。在对角线右上方的是「判高了」（把不相关判成相关），左下方是「判低了」。

**错误类型表**：每个「金标->预测」组的条数、「稳定于（层）」（该组 logit lens 里预测等级开始领先的层），以及文本 token 在归因里的占比。

**结论**自动写出：最常见的错误类型及其占比、判高 / 判低各多少条；如果某组下一个 token 的概率大多不在等级词上，会提醒先检查提示词模板和解码协议——这种情况下后面的机制分析意义不大。

> demo 用的是随机小模型，所以会出现这条提醒，数字也没有实际意义。

## 2. 逐条坏例

每条坏例一张卡片，上方有 **筛选 / 排序 / 搜索**：

- 筛选：按错误类型（例如 `3->0`），或只看 `correct`（坏例文件里有、但现在已经判对的）。
- 排序：按 id、按预测概率从高到低（模型「越自信地判错」越靠前）、按 |金标−预测| 从大到小、按「稳定于」的层从早到晚。
- 搜索：匹配 id、查询或文档里的文字。右侧显示当前可见条数。

卡片内容：

1. **标题**：id，以及「金标 X → 预测 Y」（红色标签表示判错）。
2. **图片缩略图**：样本带图时显示；图片文件找不到时显示「有图但文件找不到」。
3. **查询 / 文档**：原文。被 token 归因选中的词会用底色标出（见下）。
4. **等级概率条**：模型最终在每个等级上的概率。红条是错误的预测，绿条是金标（★ 标记），灰色是其余等级。
5. **Logit lens 折线图**：横轴是层（`embed` 表示还没进任何层），每条线是一个等级的概率——意思是「如果模型在这一层就停下来输出，会给每个等级多少概率」。红色竖虚线「稳定于 L」标出预测等级从哪一层开始一直领先到最后。
   - 很晚（最后一两层）才翻转：错误主要发生在末端的读出（最后几层、lm_head），常常可以用小补丁修。
   - 很早就领先：输入表示本身就偏了，往往和数据 / 模板有关。
   - 只有被抽样做逐层分析的样本才有这张图（配置 `max_detail_cases`，每组默认 4 条）；没有的会写明。
6. **Token 归因**：归因分数 = 该 token 对「logit(预测) − logit(金标)」的贡献（grad×input 或积分梯度，取决于 `token_attr_method`）。**红色**把答案推向错误预测，**蓝色**把答案拉回金标，颜色越深作用越大。方块里是贡献最大的几个 token 和分数，鼠标停留可看上下文；同样的词若出现在查询 / 文档原文里，也会在原文中标色。
7. **文本 vs 图像条**：归因绝对值中文本 token 和图像 token 各占多少。图像占比很高说明这条判断主要被图带偏了。注意这是语言模型入口处的 token 归因，不是像素级归因。

## 3. 组件定位

所有图都基于 **DLA（直接 logit 归因）**：把最终的「logit(预测) − logit(金标)」拆成每个注意力头、每层 MLP 的直接贡献。正值（红）= 在推错，负值（蓝）= 在往金标拉。数值对所有有逐层明细的坏例取平均。

- **层 × 头热力图**：行是层，列是头。找最红的格子。线性注意力层（GatedDeltaNet）的「头」按输出投影切分；某层没有该头时格子为灰色。
- **MLP 条形图**：每层 MLP 的平均贡献，朝右红条在推错。
- **Top-K 组件**：头和 MLP 合在一起按平均贡献排序的前 10 名。

**结论**写出贡献最大的组件及其占全部正向贡献的比例。**这是相关性，不是因果**：一个组件「贡献大」不等于关掉它就能修好。是否真的有效看第 5 节的干预结果和状态。

## 4. 微调改了什么

比较微调模型和基座模型的权重差 ΔW = W_ft − W_base。

- **ΔW / W（按张量）**：每个张量的相对变化 ‖ΔW‖/‖W_base‖，只列变化最大的前 K 个（`delta_w_top_k`），变化为 0 的会隐藏。
- **‖ΔW‖（按层）**：把上面这些张量按层（`L0`、`L1`…，以及 `lm_head`、`embed_tokens` 等）加总。只统计前 K 个张量，所以是「主要改动落在哪层」的近似。
- **SVD**：每个张量 ΔW 的前几个奇异值 σ1、σ2…。σ1 远大于其它说明这次改动几乎是一个方向（低秩），比较好解释、也比较容易精确回退。
- **lm_head 等级行**：lm_head 里每个等级 token 那一行的变化大小 ‖Δ行‖，表格里给出新旧行的余弦。余弦明显小于 1 说明这个等级的「读出方向」被微调改了——如果它正好是错误预测的等级，就是「微调让模型更爱输出这个等级」的直接证据。

几何上的改动大不等于对坏例的因果影响大；需要结合第 3、5 节一起看。

## 5. 补丁

表格每行一个补丁候选（来自 `patches/`），列：

| 列 | 含义 |
| --- | --- |
| 错误类型 | 这个补丁针对哪个组 |
| 补丁 | 方法、层、头、缩放系数，下方是补丁文件 |
| 状态 | 和全文报告相同：「消融有效」「证据不足」「仅相关」等，定义见 [修复与补丁](修复与补丁.md#报告里的状态) |
| 抽样翻转率（紫） | 分析时做的干预复核中，干预后金标 logit 超过原预测 logit 的样本比例，括号里是样本数。样本很少，只作参考 |
| 修复率（绿） | 来自 `rba eval`：原本判错、打补丁后判对的坏例比例 |
| 回退率（红） | 来自 `rba eval`：原本判对、打补丁后判错的对照样本比例 |

没跑过 `rba eval` 时后两列显示「未评估」。

**建议**按以下顺序自动给出：

1. 有状态为「消融有效」且已评估、修复率 > 0 的补丁 → 建议优先验收它，并写出修复率和回退率；
2. 有「消融有效」但没评估 → 建议先跑 `rba eval`；
3. 没有补丁通过干预复核 → 不建议直接上线，补丁只作为探索方向，建议扩大样本或用 `rba finetune`。

下方黑框是对应的验收命令，复制即可运行。决定上线前务必两个率都看：回退率高的补丁不要用。

## 6. 文字结论

把全文版「先看这里」和每组前几条假设（状态 + 标题 + 证据）原样列出，方便不打开全文报告也能看到要点。完整证据见 `report_detail.html`。

## 已知限制

- 报告只展示分析时已经算好的数据，不会补算。逐层图、DLA 只覆盖被抽样做逐层分析的坏例（`max_detail_cases`）。
- Token 归因只保存了每条样本贡献最大的几个 token，所以原文标色只覆盖这些词；分词结果和原文对不上的 token（如子词、特殊符号）只出现在方块列表里。
- ΔW 按层的图只统计变化最大的前 K 个张量。
- 第 5 节只读取 `eval/eval.json`（以及 `eval*.json`、`evals/*.json`）。默认每次 `rba eval` 会覆盖 `eval/eval.json`，所以只显示最后一次验收；要同时显示多个，把各次结果另存到 `evals/` 下再运行 `rba report`。
- 抽样翻转率比较的是金标和原预测两个 logit，不等于整体 argmax 一定变成金标。
