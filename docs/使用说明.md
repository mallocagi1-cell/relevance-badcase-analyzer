# rba 详细使用说明

这份文档是参考手册。第一次用请先看仓库首页的 [README](../README.md)，5 分钟就能跑出报告。这里写全部命令、参数、数据格式、报告细节、方法、显存、常见问题和已知限制。

## 安装

需要 Python 3.10+、PyTorch、transformers 5.x。在仓库根目录：

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e .          # 想跑测试用 pip install -e ".[dev]"
```

不会下载任何模型权重。真实模型请自己准备好两个本地目录：基座（微调前）和微调后，各自含 `config.json` 和 safetensors 权重。

## 子命令一览

| 命令 | 做什么 |
| --- | --- |
| `rba demo [--arch tiny\|qwen3_5_tiny] [--output-dir D]` | 用内置小模型和样例数据干跑一遍，确认环境没问题 |
| `rba init --base B --ft F --badcases X [--goodcases Y] [--out rba.yaml]` | 生成一份带注释、可修改的配置文件 |
| `rba analyze ...` | 跑分析，写可视化 `report.html`、全文 `report_detail.html` / `report.md`、`report.json` |
| `rba report <输出目录>` | 从已有输出目录重新生成 `report.html`，不加载模型、不重算；`--language zh/en` |
| `rba eval --run 输出目录 --patch 补丁.json` | 在验收集（或发现集）和对照集上评估一个补丁 |

`python -m rba ...` 和 `rba ...` 等价。

`analyze` 的参数：`--config`、`--base`、`--ft`、`--badcases`、`--goodcases`、`--output-dir`、`--device auto|cpu|cuda`、`--batch-size`（0 自动）、`--seed`、`--decode-protocol constrained|free`、`--language zh|en`、`--allow-missing-images`、`--dry-run`、`--fresh`、`--max-cases N`、`--holdout 比例`。命令行写了的字段会盖掉配置文件里的同名字段。每个参数的作用见下文「命令行参数全表」。

## 分析真实模型


```bash
rba analyze \
  --base /path/to/base \
  --ft /path/to/Qwen3.5-VL-2B-ft \
  --badcases bad.jsonl \
  --goodcases good.jsonl
```

程序先检查两个目录都有 `config.json` 和权重，读 `config.json` 认架构，加载微调模型的分词器和处理器，核对每个等级是不是单个 token，再加载权重。基座不进 GPU，ΔW 按张量从磁盘读。

想先生成一份带注释的配置：

```bash
rba init --base /path/to/base --ft /path/to/ft --badcases bad.jsonl --goodcases good.jsonl
rba analyze --config rba.yaml --dry-run
```

`--dry-run` 把提示词和证据包写到输出目录的 `prompts/`，不访问网络。去掉它才会用 `llm.api_key_env`（默认 `OPENAI_API_KEY`）去请求 `llm.base_url`。密钥没设置时，程序照常完成分析，只是等同于 `--dry-run`，并在报告里写一条注意。接口调用失败也不会丢报告：失败的组记在 `report.json` 的 `llm_failures`，进程退出码 3，修好后重跑同一条命令会从缓存接着用。

同一条命令再跑会接着用缓存。换了数据或配置会拒绝混进旧目录，这时加 `--fresh`，或换一个 `--output-dir`。

常用参数：

| 参数 | 作用 |
| --- | --- |
| `--decode-protocol constrained\|free` | `constrained` 只在等级 token 里取 argmax；`free` 用全词表 argmax，落在等级外算非法输出，单独统计 |
| `--holdout 0.5` | 按 id 哈希留出一半坏例不参与选补丁，只给 `rba eval` 用 |
| `--allow-missing-images` | 图片读不到时剔除该样本并写进报告，而不是停下 |
| `--max-cases N` | 只取前 N 条坏例试跑 |
| `--fresh` | 忽略并覆盖输出目录里的缓存 |

退出码：0 成功；2 配置或数据错误（已给出建议）；3 分析完成但大模型调用失败；1 程序内部错误，完整 traceback 在输出目录的 `error.log`。

## 验收补丁

报告里每条推荐假设带一条命令：

```bash
rba eval --run runs/example --patch runs/example/patches/3_to_0_h2.json
```

`--run` 完整恢复那次分析的配置（模板、等级 token、解码协议、模块路径、dtype、设备语义），不会悄悄换成别的实验。`eval` 报告两个条件率：坏例修复率和对照回退率，各带 95% Wilson 区间，再加净正确数变化和新增非法输出数。两个条件率来自不同人群，不能直接相减当作线上净收益；净收益取决于线上错误占比。

只有设了 `holdout_fraction`（或 `--holdout`）时，坏例侧才是没有参与选补丁的**验收集**；否则结果写成「发现集复评」，不代表泛化。配置里默认是 0（示例数据只有 8 条），`rba init` 给真实模型写的是 0.5。

补丁只在本次进程里生效，不会把 2B 权重另存一份。当 `lm_head` 和输入 embedding 共享权重时，`lm_head_blend` 这类行编辑会同时改掉该等级 token 的输入表示：报告会标出来，`eval` 本轮拒绝验收这种补丁。

## 数据

`jsonl` 每行一个对象，或带表头的 `csv`。必填 `query`、`label`，以及 `doc` / `image` 至少一个。`prediction` 可空，程序会重跑。`attributes` 是给探针和分组回退统计用的对象；CSV 用 `attr_` 前缀。

```json
{"id": "b001", "query": "红烧肉怎么做", "doc": "五花肉焯水后炖四十分钟。", "image": "images/sample.ppm", "label": 3, "prediction": 0, "attributes": {"domain": "food"}}
```

完整例子在 `examples/badcases.jsonl`、`examples/goodcases.jsonl`、`examples/badcases.csv`。图片路径相对样本文件所在目录。读不到的图片不会被悄悄当成纯文本：默认停下并指出是哪条；加 `--allow-missing-images`（或配置 `missing_image: exclude`）会剔除这条样本并写进报告的「剔除的样本」。

`label` 必须落在 `grades` 里。默认五个字符串：`-1`、`0`、`1`、`2`、`3`。

## 等级 token 协议

`grade_mode: single_token`（默认）要求每个等级本身就是分词器里的一个 token。若某个等级被切成多个子词（`-1` 经常是 `-` 和 `1`），程序在加载权重前报错，并把实际切分写出来。

只有训练协议确实是「按首 token 分类」时，才声明 `grade_mode: first_token`：程序要求各等级的首 token 两两不同，报告和证据包都会标明这是首 token 分类器，不是完整序列的似然。`grade_token_ids` 可以手写，但键必须是字符串、值必须等于分词器对该等级的首 token id；它不是绕过多 token 错误的捷径。

## 解码协议

线上怎么解码，这里就怎么评。`decode_protocol: constrained` 只在等级 token 的 logit 里取 argmax；`free` 用全词表 argmax，等级外的输出记为非法，单独列在报告的「非法输出」里，不进入按等级索引的归因。两种协议都会报告全词表 top 是等级词的比例和等级词概率质量。`eval` 还会报告补丁有没有新增非法输出。

## 模板和图片

`prompt_template` 必须和微调时的输入一致，并且停在「下一个 token 就是等级」的位置，不要把答案写进去。占位符只有 `{query}`、`{doc}`、`{image}`。

真实模型的输入全部走它自己的处理器，有图和无图样本用同一套协议：

* `input_mode: template`：`{image}` 换成 `image_placeholder`（默认 `<|vision_start|><|image_pad|><|vision_end|>`），处理器按原图分辨率决定图像 token 数并打包视觉张量。模板里有图片样本却没有 `{image}` 会报错。
* `input_mode: chat`：所有样本（包括纯文本）走处理器的对话模板。
* `input_mode: auto`：处理器带 chat_template 就用 chat，否则 template。

图片不会被预先缩放。`image_max_pixels`（默认 262144）传给处理器，用来控制图像 token 数和显存。`max_length` 截断只截开头的文本 token，碰到图像块会报错而不是切一半。带处理器视觉张量的样本这一轮逐条前向（batch 1），程序会说明。

内置小模型（`tiny`）自己把 8×8 的图片散到 `image_token` × `image_seq_len` 个位置上，用来测文本/图像归因；`qwen3_5_tiny` 是真实类的随机小模型，没有处理器，图片不进入模型，只保留占位 token。

## 报告里有什么

`report.html` 是可视化报告（总览热力图、逐条坏例卡片、组件定位、ΔW、补丁，每张图配「怎么看」和自动结论），详见 [可视化报告](可视化报告.md)。`report_detail.html` 和 `report.md` 是全文版，内容相同（HTML 由同一份 Markdown 渲染）。开头是按组排好的假设，每条有状态、证据、证据编号、会推翻它的观察和下一步命令。然后是概览（含协议、非法输出和剔除样本）、图、证据（归因表、读出分解可靠性、token 归因、带对照的干预复核表）、ΔW、探针、给大模型的提示词和回复，最后是方法说明和状态表。`report.json` 是同一份结构，还包含逐例的复核差值。

### 报告里的状态

每个状态的精确判定条件见 [修复与补丁](修复与补丁.md#报告里的状态)。

| 状态 | 含义 |
| --- | --- |
| 消融有效 | 在该组抽样上，决策位置的目标干预让 logit(原预测)−logit(金标) 下降，且多数样本同向。只说明干预有效，不是根因证明 |
| 仅相关 | 归因或 ΔW 指向它，但没做干预，或只做了诊断性干预（lm_head 行混合代数上必然缩小两行差距） |
| 被复核否定 | 干预反而让误差变大。留在列表里，不拿去当根因 |
| 消融无效果 | 干预几乎不改变错误 logit |
| 复核不稳定 | 效果在样本之间方向不一致 |
| 证据不足 | 读出分解对不上、identity 对照非零、随机对照同样有效，或选择样本与复核样本没有分开 |
| 先处理这个 | 等级词上几乎没有概率质量，或全词表 argmax 不是等级词。先核对模板和解码协议 |

没有「置信度」数字：没有校准过的数字不会出现在报告里，只有上面的证据强度。

## 方法（给要核对公式的人）

决策位置是最后一个非填充 token。

Logit lens：每一层残差过模型自己的最终 RMSNorm，再读等级行，同时保留 logit 和条件概率。最后一层应当和真实等级分布一致，这是接线检查。

读出归因：方向 `d = W_U[原预测] − W_U[金标]`。报告里的组件归因是最终 RMSNorm 之后、按真实 norm 增益和最终残差尺度折算的贡献，嵌入入口加各层注意力写入和 MLP 写入应当重建真实 logit 差，重建误差和「可靠」标记一起写出；旧的 norm 前点积只作诊断。头的切分在输出投影上：全注意力是 `o_proj`，GatedDeltaNet 是 `out_proj`。

干预复核在决策位置做（头的输出切片乘系数、MLP 在该位置清零、该位置加 steering 向量），每个目标带同类随机对照和 identity 对照；组里样本够多时复核用没参与选择的样本。`lm_head` 行混合只作诊断。

ΔW 只说明微调动过哪里。奇异向量成对保留并给出解释能量，符号任意；只有输出维就是残差维的矩阵才投到等级词上，没有样本激活系数时不说某个方向「促进」某个等级。共享参数只计一次。

Token 归因是语言层入口上的 grad×input 或积分梯度，按图像 token id 和文本切开；积分梯度写出零基线、端点和完整性误差。这不是像素梯度，也不是图像 token 数量占比。

探针是属性上的岭回归，交错抽取坏例和对照，报告留出一半和多数类基线，不进入根因排序。

## 显存、GPU 与 bf16

真实模型建议 `device: cuda`、`dtype: bfloat16`（`auto` 在 GPU 上会选 bf16）。bf16 下部分绝对阈值偏严，见文末「已知限制」。


2B、bf16，单卡大约 5GB 再加激活。默认只把微调模型放到 GPU；基座用 safetensors 逐张量读，SVD 有维度上限。batch 默认很小，遇到 OOM 会减半重试；减到 1 还不够时会停下并按顺序给出可调项（`max_length`、`image_max_pixels`、`token_attr_method: gradxinput`、关掉 `token_attr` 或 `force_eager_attn`）。归因和复核只跑每组最多 `max_detail_cases` 条（默认 4）。CPU 上 dtype 会被改成 float32。

GatedDeltaNet 层在没有 `flash-linear-attention` / `causal-conv1d` 时走 transformers 的 PyTorch 参考实现：结果正确，速度慢。这两个包依赖 CUDA 工具链，不作为默认依赖，见 `pyproject.toml` 的注释。

## Qwen3.5-VL 的模块名

在 transformers 5.22 里核对过：

| 用途 | 路径 |
| --- | --- |
| 类 | `Qwen3_5ForConditionalGeneration` |
| 处理器 | `Qwen3VLProcessor`（`AutoProcessor` 自动选） |
| 语言层 | `model.language_model.layers` |
| 全注意力 | `self_attn`（`q_proj` `k_proj` `v_proj` `o_proj`） |
| 线性注意力 | `linear_attn`（GatedDeltaNet，写入在 `out_proj`） |
| MLP | `mlp.gate_proj` / `up_proj` / `down_proj` |
| 最终 norm | `model.language_model.norm` |
| 视觉塔 | `model.visual` |
| 输出头 | `lm_head` |

这个版本**没有** `Qwen3_5VLForConditionalGeneration`。加载时会先试 `config.json` 里的 `architectures`，再试上表这个类名，然后才是 `AutoModelForImageTextToText`。`module_paths` 留空（`rba init` 默认注释掉）则在模块树上自动发现；手写错了会报中文错误并给出自动发现的候选。

## 命令行参数全表

命令行写了的字段会盖掉配置文件里的同名字段；没写的保持配置文件里的值。

### `rba init`

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `--base` | `tiny` | 基座模型目录 |
| `--ft` | `tiny` | 微调模型目录。只读 `config.json`，不加载权重 |
| `--badcases` | `examples/badcases.jsonl` | 坏例文件 |
| `--goodcases` | `examples/goodcases.jsonl` | 对照文件 |
| `--out` | `rba.yaml` | 写到哪里。文件已存在会报错，不覆盖 |

`init` 会按本机有没有 GPU 写 `device`/`dtype`（有 GPU：`cuda`/`bfloat16`；否则 `cpu`/`float32`），真实模型写 `holdout_fraction: 0.5`、`plant_error: false`。

### `rba analyze` 和 `rba eval` 共用

| 参数 | 对应配置键 | 含义 |
| --- | --- | --- |
| `--config 文件` | — | YAML 配置 |
| `--base 目录` | `base_model` | 基座目录，或 `tiny` / `qwen3_5_tiny` |
| `--ft 目录` | `ft_model` | 微调目录，或 `tiny` / `qwen3_5_tiny` |
| `--badcases 文件` | `badcases` | 坏例 jsonl/csv |
| `--goodcases 文件` | `goodcases` | 对照集 |
| `--output-dir 目录` | `output_dir` | 输出目录 |
| `--device auto\|cpu\|cuda` | `device` | 设备 |
| `--batch-size N` | `batch_size` | 0 自动 |
| `--seed N` | `seed` | 随机种子 |
| `--decode-protocol constrained\|free` | `decode_protocol` | 解码协议 |
| `--language zh\|en` | `language` | 大模型回答语言 |
| `--allow-missing-images` | `missing_image: exclude` | 图片读不到时剔除样本 |

命令行给的相对路径按**当前目录**解析；配置文件里的相对路径按**配置文件所在目录**解析。

### 只属于 `rba analyze`

| 参数 | 含义 |
| --- | --- |
| `--dry-run` | 只写提示词，不调用大模型 |
| `--fresh` | 清空该输出目录的缓存，全部重算 |
| `--max-cases N` | 只取前 N 条坏例（在剔除验收集之后） |
| `--holdout 比例` | 设 `holdout_fraction` |

零配置时（不传 `--config`），`--base`、`--ft`、`--badcases` 三个都必填，且 `goodcases` 默认为空。

### 只属于 `rba eval`

| 参数 | 含义 |
| --- | --- |
| `--patch 文件` | 必填。补丁 JSON |
| `--run 目录` | 某次 analyze 的输出目录，完整恢复配置。不能和 `--config` 同时用。不写 `--output-dir` 时结果写到 `<run>/eval/eval.json` |

不用 `--run` 也不用 `--config` 时，`--ft` 和 `--badcases` 必填，`--base` 默认等于 `--ft`。eval 永远不调用大模型。补丁字段详见 [修复与补丁](修复与补丁.md)。

### `rba demo`

| 参数 | 默认 | 含义 |
| --- | --- | --- |
| `--arch tiny\|qwen3_5_tiny` | `tiny` | `tiny` 是同结构替身；`qwen3_5_tiny` 是真实类的随机小模型 |
| `--output-dir` | `runs/demo` | 输出目录 |

demo 必须在仓库根目录运行（要找到 `example.yaml` 和 `examples/`）。它固定用 CPU、float32、dry-run，并且每次都 `--fresh`。

## 配置键全表

配置文件是 YAML。**不认识的键会直接报错**，并列出所有可用键，避免拼错后被悄悄忽略。下表来自 `src/rba/config.py`。

### 模型与数据

| 键 | 类型 | 默认 | 含义 |
| --- | --- | --- | --- |
| `base_model` | 字符串 | `tiny` | 基座目录。ΔW 用它；基座不进 GPU |
| `ft_model` | 字符串 | `tiny` | 微调目录。所有推断、归因、干预都在它上面做 |
| `model_type` | `auto` / `tiny` / `qwen3_5_tiny` / `hf` | `auto` | 模型种类。`auto` 按目录名判断 |
| `model_class` | 字符串或空 | 空 | 强制用这个 transformers 类名加载。空则先用 `config.json` 的 `architectures` |
| `badcases` | 路径 | `examples/badcases.jsonl` | 坏例文件 |
| `goodcases` | 路径或空 | `examples/goodcases.jsonl` | 对照文件。空则看不出回退 |
| `module_paths` | 映射 | `{}` | 手动指定模块路径，键有 `layers`、`lm_head`、`visual`、`final_norm`。值写空、`auto` 或不写都表示自动发现 |

## 输入数据字段

文件格式：`.jsonl` / `.json`（每行一个对象）或带表头的 `.csv`。其他扩展名报错。空文件报错。

| 字段 | 必填 | 含义 |
| --- | --- | --- |
| `query` | 是 | 查询文本 |
| `doc`（别名 `document`） | 与 `image` 至少一个 | 文档文本 |
| `image`（别名 `image_path`） | 与 `doc` 至少一个 | 图片路径。相对路径先按样本文件所在目录找，再按当前目录找 |
| `label` | 是 | 金标等级。必须在 `grades` 里；`3.0` 这种整数值浮点会转成 `3` |
| `id` | 否 | 样本 id。不写自动编成 `c0001`… 同一文件内重复会加 `#2`、`#3` 后缀；**坏例和对照之间 id 必须不同**（建议 `b001` / `g001`） |
| `prediction`（别名 `pred`） | 否 | 线上预测。程序总会重新推断，这个只做记录 |
| `attributes` | 否 | 对象，例如 `{"domain": "food"}`。给探针和 eval 的按属性统计用。CSV 里写成 `attr_domain` 这样的列 |
| `note` | 否 | 备注 |

额外的校验：

* 同一内容（query、doc、image 完全相同）以不同 id 同时落进发现集和验收集，会报错，要求先去重。
* 和验收集内容相同的对照样本会被剔除，写进报告的「剔除的样本」。

## 分析的 8 个阶段

| 阶段 | 做什么 | 缓存名 |
| --- | --- | --- |
| 1 | 加载模型、对齐模块路径、检测共享权重 | — |
| 2 | 编码样本（剔除验收集、应用 `max_cases`） | — |
| 3 | 重新推断坏例和对照 | `infer_bad`、`infer_good` |
| 4 | ΔW | `delta` |
| 5 | logit lens、读出归因、注意力 | `mech` |

| 7 | 干预复核（目标 + 随机对照 + identity 对照） | `verify` |
| 8 | 假设、提示词、调用大模型、写补丁和报告 | — |

## 缓存和续跑

* **指纹。** 每次 analyze 先算一个指纹：缓存版本号 + 几乎全部配置 + 模型身份（配置/分词器/处理器文件的 sha256，权重文件的大小和修改时间）+ 坏例、对照、图片文件的身份。`device`、`batch_size`、`output_dir`、`llm` 子配置、`language` 不进指纹。
* **命中。** 某阶段的缓存记录指纹和当前一致、文件还在，就直接读，终端打印"从缓存恢复：…"。
* **换了东西。** 同一输出目录里有不同指纹的缓存时，analyze 报错拒绝混用。加 `--fresh`，或换 `--output-dir`。
* **旧版本缓存。** 旧版本 rba 写的缓存（`cache_schema` 不同）会自动清掉重算，只打印一条注意。
* **中断。** Ctrl-C 退出码 130。已完成的阶段留在 `cache/`，同一命令再跑从下一个阶段继续。
* **大模型失败。** 分析阶段全在缓存里。修好密钥或网络后重跑同一命令，只重做阶段 8。
* **不写输出目录时**，目录名就是指纹前 12 位，所以换了数据会自动进新目录。
* `rba eval` 不读也不写缓存，每次都重新推断。

## 报告各部分

`report.md` / `report_detail.html` 的章节顺序（可视化 `report.html` 的章节见 [可视化报告](可视化报告.md)）（`report/render.py`）：

| 章节 | 内容 | 怎么用 |
| --- | --- | --- |
| 先看这里 | 总结一句话，然后按混淆组列假设：状态、标题、证据、证据编号、会推翻它的观察、`rba eval` 命令 | 从这里开始读。只看带命令的条目 |
| 这次跑了什么 | 模型、设备、dtype、协议、样本数、准确率、合法输出率、验收集划分、注意事项 | 核对是不是你想跑的实验 |
| 非法输出 | 全词表 argmax 不是等级词的样本（解码后的 top token + id） | 有很多时先修模板 |
| 剔除的样本 | 图片读不到、与验收集重复等被剔除的样本和原因 | 核对数据 |
| 图 | 上面 5 张图 | — |
| 证据 | 每组：读出归因表、分解可靠性、token 归因、干预复核表（目标、随机、identity）；然后 ΔW、探针 | 判断假设靠不靠谱 |
| 给前沿模型的提示词 | 提示词文件链接；大模型回复（解析后的 JSON） | 交给大模型继续分析 |
| 方法说明 | 方法和状态含义表 | 核对公式 |

**怎么读一条假设：** 状态（见「报告里的状态」）告诉你证据强度；"干预错误 logit 差均值变化"越负越好；"随机对照下降不少于目标"说明不是这个组件特有的；"选择与验证样本未证明独立"说明复核样本和挑选样本有重叠；"证据不足原因"写明为什么不足。

## 输出语言

报告（`report.md` / `report.html`）的标题、假设、下一步建议、命令行摘要都是中文。`report.json` 的键名保持英文，便于脚本读取。

配置项 `language`（命令行 `--language`）默认 `zh`：发给大模型的提示词会明确要求「全部用中文回答，JSON 键名保持英文，logit lens、DLA、ΔW 等术语保留原文」。设成 `en` 让大模型改用英文回答，可视化 `report.html` 的标题和说明也改成英文；全文版 `report_detail.html` / `report.md` 仍是中文。

## 常见问题

**报告每组第一条都是「先处理这个：概率大多不在等级词上」？** 内置小模型是随机的，这条是正常的检查。真实模型上出现它，说明 `prompt_template` 或解码协议和训练时不一致，先修模板，再看后面的假设。

**报错「等级被切成多个 token」？** 分词器把比如 `-1` 切成了 `-` 和 `1`。确认训练协议；只有真的按首 token 分类时才设 `grade_mode: first_token`。

**报错「换了数据或配置，拒绝混进旧目录」？** 加 `--fresh`，或换一个 `--output-dir`。

**没设 API 密钥会怎样？** 分析照常跑完，等同于 `--dry-run`，提示词写在 `prompts/`，报告里会注明。

**退出码 3？** 分析完成但大模型调用失败。失败的组在 `report.json` 的 `llm_failures`，修好网络或密钥后重跑同一条命令，会从缓存续跑。

**OOM？** batch 会自动减半。到 1 还不够，依次调小 `max_length`、`image_max_pixels`，用 `token_attr_method: gradxinput`，或关掉 `analyses.token_attr`。

**图片读不到？** 默认停下并指出是哪一条。加 `--allow-missing-images` 会剔除这条并写进报告。

**程序内部错误（退出码 1）？** 完整 traceback 在输出目录的 `error.log`。

## 已知限制

* **bf16 下的绝对阈值。** 一些判定（例如 identity 对照「接近 0」、分解重建误差）用的是 1e-4 量级的绝对阈值。bf16 精度下这些阈值可能偏严，容易把正常结果判成「证据不足」。需要严格判定时用 `dtype: float32`（显存约翻倍），或把这类结论当作提示而非定论。
* **2B 模型上跳过 lm_head 的 SVD。** `lm_head` 是「词表 × 隐藏维」的大矩阵，超过 `svd_max_dim` 不做低秩分解，ΔW 部分只给范数等统计，不给 lm_head 的奇异方向。
* **每组少于 4 条 = 证据不足。** 某个混淆组（如 `3->0`）复核样本少于 4 条时，不管干预效果多好，状态都标「证据不足」。想得到有效结论，每组至少准备 4 条，最好 8 条以上，并设 `holdout_fraction`。
* 「消融有效」只说明干预在样本上有效，不是根因证明。
* 修复率和回退率是两个不同人群上的条件率，不能直接相减当线上净收益。
* 补丁只在进程内生效，不会另存权重；共享权重的 `lm_head` 行编辑会被 `eval` 拒绝。
* 报告固定为中文，`language: en` 只影响大模型的回答。
