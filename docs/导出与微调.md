# 导出与微调

`rba eval` 只是在推理时用钩子临时施加补丁，量一下修复率和回退率，不改模型文件。
这份文档讲接下来的两步：

- `rba export`：把验收过的补丁**精确**改进权重，存成一个普通的 Hugging Face 模型目录。
- `rba finetune`：补丁修不好（或回退太多）时，在定位到的那几层上做一次小范围修复训练。

两条命令都和 `rba eval` 一样，可以用 `--run 分析目录` 恢复那次分析的全部配置（模板、等级、解码协议、模块路径、验收集划分），也可以直接给 `--ft / --badcases / --goodcases`。

---

## 一、rba export：把补丁烘焙进权重

### 它做了什么

1. **先检查补丁能不能精确烘焙**（不加载模型，不行就立刻停下，见下面「什么会被拒绝」）。
2. 加载微调模型，用坏例 + 对照集做三次打分：
   - 原模型（改前）；
   - 原模型 + 钩子补丁（就是 `rba eval` 里的那种，所有补丁按给出的顺序叠加）；
3. 按顺序把每个补丁改进权重，`save_pretrained` 写到 `--out`，再把分词器 / 处理器文件（tokenizer.json、tokenizer_config.json、chat_template、preprocessor_config.json 等）从源目录复制过去。
4. **从导出目录重新加载**（不带任何 rba 钩子），再打一次分。
5. 对比「钩子补丁」和「导出模型」：每条样本的等级 logit 最大差值要在容差内、预测要逐条一致。不一致就报错（退出码 2），目录保留供检查，**不要上线**。
6. 写 `rba_export_manifest.json`，并打印导出模型相对原模型的修复率 / 回退率。

导出的目录可以直接 `Qwen3_5ForConditionalGeneration.from_pretrained(目录)` 或 `AutoProcessor.from_pretrained(目录)` 使用，不需要安装 rba。

### 每种补丁怎么烘焙

| 补丁 | 改哪里 | 是否精确 |
|---|---|---|
| `head_scale` | 该层注意力输出投影里这些头对应的**输入列**乘以 scale。全注意力层是 `self_attn.o_proj`，线性注意力（GatedDeltaNet）层是 `linear_attn.out_proj` | 精确（所有位置） |
| `mlp_zero` | 该层 `mlp.down_proj` 的权重（和 bias，如果有）置零 | 精确（所有位置） |
| `lm_head_blend` | 把 `lm_head` 里该等级那一行换成 `(1-alpha)·自己 + alpha·目标等级行` | 精确；共享 embedding 时见下 |
| `steering` | 在层输出上加常数向量 = 给该层 `mlp.down_proj` 的 bias 加上 `alpha·向量` | 只有 down_proj **本来就有 bias** 时才精确；否则拒绝 |
| `ablate_tokens` / `ablate_image` | — | 不能烘焙，拒绝 |

为什么 steering 在 Qwen3.5 上会被拒绝：Qwen3.5 的线性层都不带 bias。硬塞一个 bias 张量进 checkpoint，标准模型类加载时会把它当成多余的键丢掉，导出的模型就和补丁不等价了。o_proj 的 bias 也不行：注意力输出后面还有 post_attention_layernorm 和 MLP，常数会被 MLP 看到，不等于直接加在层输出上。

为什么 ablate 不能烘焙：它是「输入里出现某个 token（如图像 token）时，把那几个位置清零」，取决于每条输入的内容，没有一个固定的权重修改与它等价。

多个补丁按命令行给出的顺序烘焙，钩子版本也按同样顺序叠加。同一层的两个 head_scale 会相乘（组合），不会互相覆盖。

### 什么会被拒绝（以及怎么放行）

| 情况 | 默认 | 放行方式 |
|---|---|---|
| `ablate_tokens` / `ablate_image` | 拒绝 | 不能放行 |
| 补丁没有按原样复核过（`untested: true` 或 `verified_on_sample: false`） | 拒绝 | `--force` |
| 补丁状态是「被复核否定」或「消融无效果」 | 拒绝 | `--force` |
| head_scale / mlp_zero / steering 的 `scope` 是 `decision`（只改最后一个位置） | 拒绝：权重修改会作用于所有位置，行为不同 | `--allow-all-positions`（会警告；等价性核对对比的是所有位置的钩子版本） |
| lm_head 与输入 embedding 共享权重，又要导出 lm_head_blend | 拒绝：改行会同时改该 token 的输入表示 | `--untie-embeddings`（拆成独立 lm_head，config 里 `tie_word_embeddings=false`，checkpoint 会多一份 lm_head 权重） |
| steering 所在层的 down_proj 没有 bias | 拒绝 | 不能放行；改用钩子或 `rba finetune` |
| `--out` 已经有文件 | 拒绝 | `--overwrite`（清空该目录） |
| 内置小模型（tiny / qwen3_5_tiny） | 拒绝：不是标准 HF checkpoint | 用真实模型目录 |

注意：`rba analyze` 写出的补丁默认是 `scope: decision`（复核时只改决策位置）。要导出，建议先把补丁复制一份，改成 `"scope": "all_positions"`，用 `rba eval` 重新量修复率和回退率，满意了再导出；或者直接 `--allow-all-positions`，以导出后清单里的数字为准。

### 参数

| 参数 | 说明 |
|---|---|
| `--patch 补丁1.json [补丁2.json ...]` | 必填。一个或多个补丁，按顺序烘焙 |
| `--out 目录` | 必填。导出目录 |
| `--run 分析目录` | 恢复那次分析的配置；核对样本也用那次的坏例 / 对照 |
| `--config / --base / --ft / --badcases / --goodcases` | 不用 `--run` 时直接给。核对至少要有坏例；有对照集才能看到回退率 |
| `--dtype float32/bfloat16/float16` | 加载、烘焙、保存的精度。默认沿用配置。CPU 上一律 float32 |
| `--device auto/cpu/cuda` | 设备 |
| `--force` | 放行未复核 / 被否定的补丁 |
| `--allow-all-positions` | 放行只在决策位置复核过的补丁 |
| `--untie-embeddings` | lm_head 与 embedding 共享时先拆开 |
| `--tolerance 数值` | 等价性核对的 logit 容差。默认 float32 1e-3、bfloat16 0.25、float16 0.05 |
| `--overwrite` | 清空已存在的 `--out` |
| `--check-only` | 只检查补丁能否烘焙（会加载模型以检查共享权重），不写任何文件 |
| `--batch-size / --decode-protocol / --allow-missing-images` | 同 `rba eval` |

### 例子

```bash
# 导出一个补丁
rba export --run runs/xxxx --patch runs/xxxx/patches/3_to_0_h1.json --out exported/v1

# 两个补丁一起导出，模型是共享 embedding 的，补丁里有 lm_head_blend
rba export --run runs/xxxx --patch p_head.json p_blend.json --untie-embeddings --out exported/v2

# 不用分析目录，单卡 bf16
rba export --ft /models/ft --badcases holdout_bad.jsonl --goodcases control.jsonl \
  --patch p.json --dtype bfloat16 --device cuda --out exported/v3
```

### 清单 rba_export_manifest.json

- `patches`：每个补丁的文件名、方法、内容哈希、复核时的 scope 和状态、实际改了哪些权重（列区间、行号、系数）以及补丁原文；
- `source_fingerprint` / `exported_fingerprint`：源目录和导出目录的文件指纹；
- `equivalence`：样本数、dtype、容差、最大 logit 差、预测不一致的样本（`pred_mismatch`）和容差内的并列（`near_ties`，低精度下 top-2 几乎相等时允许翻转，单独列出）；
- `eval`：导出模型相对原模型在验收集（`bad_holdout`）、发现集（`bad_discovery`）、对照集（`good`）上的修复率、回退率、Wilson 区间、净正确数；
- `untied_lm_head`、`notes`（如 scope 被扩大、强制导出）、`excluded`。

### 限制

- 等价性核对只覆盖你给的坏例和对照样本，不是对所有输入的证明；但每种烘焙在数学上都是精确的，差异只来自浮点运算顺序。
- bf16 下「先缩放权重再乘」和「先乘再缩放」舍入不同，logit 会有小差异；默认容差 0.25 是按 2B 模型 logit 量级给的，可以用 `--tolerance` 收紧，或用 `--dtype float32` 导出后再转。
- 导出时整个模型会加载两次（原模型和导出目录，前一个会先释放），磁盘上会多一份完整权重。

## 二、rba finetune：针对性修复训练

### 什么时候用

补丁修不好、回退太高、或者错误是 ablate 这类不能烘焙的机制。finetune 只在分析定位到的层上动一点点参数，并用对照集回放压住回退。

### 它做了什么

1. **划分数据**
   - 坏例：分析时留出的验收集（`holdout_fraction`）只做评估，其余用来训练。分析时没留出的话，这次按 id 哈希留出 `--train-holdout`（默认 30%），并提示这些样本参与过选层，不完全独立。
   - 对照集：按 id 哈希，`--control-holdout`（默认 50%）留作评估，其余做回放。和留出坏例内容重复的对照会被剔除。
   - `--extra-train`：额外训练数据，只进训练。
2. **定位训练目标**：读 `--run` 目录里的 `report.json`，优先取状态「消融有效」的补丁，其次是推荐的，再其次是所有带补丁的假设：
   - head_scale / mlp_zero / steering 涉及的层 → 这些层的注意力输出投影（`o_proj` 或 `out_proj`）和 `mlp.down_proj`（都是直接写残差流的模块）；
   - lm_head_blend → `lm_head`。
   - 没有报告、报告里也没有补丁 → 最后两层，并给出警告。
   - `--layers` / `--modules` 可以手动覆盖；`--targets all` 训练所有层。
3. **难负例挖掘**：先用原模型给训练坏例打分，每条坏例当前判成的错误等级就是它的难负例（形成混淆对，如 `3->0`）。对照集里「金标相同、第二名正好是某个混淆等级」的样本算难对照，权重加倍。默认按混淆组均衡采样，每组被抽到的机会相同（`--no-balance-groups` 关掉）。
4. **损失**（只看决策位置那一个 token，且只在等级 token 上做 softmax）：
   - 所有样本：对等级 token 的交叉熵；
   - 有难负例的样本：`hard_negative_weight × max(0, margin − (金标 logit − 混淆等级 logit))`；
   - 回放的对照样本：再加 `kl_weight × KL(原模型等级分布 ‖ 新模型等级分布)`，让原本对的样本别动。
   - 每步 `train_batch_size` 条，其中 `replay_ratio` 比例来自对照回放。
5. **合并保存**：LoRA 适配器合并回权重，去掉 LoRA 包装，`save_pretrained` 到 `--out/model/`，复制分词器文件。得到的是普通 checkpoint，可以再交给 `rba eval` / `rba analyze`。
6. **前后对比**：在留出坏例、留出对照、训练坏例上分别报告准确率、修复率、回退率（同 `rba eval` 的配对统计），写 `--out/finetune.json`（含每步 loss 曲线）。

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--out 目录` | 必填 | 写 `model/` 和 `finetune.json` |
| `--run 分析目录` | — | 恢复配置，并从 `report.json` 读定位结果 |
| `--config / --base / --ft / --badcases / --goodcases` | — | 不用 `--run` 时直接给 |
| `--dtype` | 沿用配置 | 2B 单卡用 `bfloat16` |
| `--device` | 沿用配置 | `cuda` / `cpu` |
| `--mode lora/full` | `lora` | lora 需要 peft；full 直接训练目标模块的全部权重 |
| `--targets localized/all` | `localized` | 只训定位到的层，或所有层 |
| `--layers 3,5` | — | 手动指定层，盖掉报告 |
| `--modules o_proj,out_proj,down_proj,lm_head` | 各层输出投影 + down_proj | 线性层名字的最后一段 |
| `--extra-train 文件` | — | 额外训练数据，格式同坏例 |
| `--steps` | 100 | 优化步数 |
| `--lr` | LoRA 1e-4，full 1e-5 | 学习率 |
| `--train-batch-size` | 4 | 每步样本数（带处理器视觉输入时逐条前向、梯度累加） |
| `--lora-r` / `--lora-alpha` | 8 / 16 | LoRA 秩和缩放 |
| `--hard-negative-weight` | 1.0 | 难负例间隔损失权重，0 关掉 |
| `--margin` | 1.0 | 金标 logit 要比混淆等级高出的量 |
| `--replay-ratio` | 0.5 | 每步里对照回放的比例 |
| `--kl-weight` | 1.0 | 回放样本的 KL 权重 |
| `--control-holdout` | 0.5 | 对照集留作评估的比例 |
| `--train-holdout` | 0.3 | 分析没留验收集时，这次留出的坏例比例 |
| `--no-balance-groups` | 关 | 不按混淆组均衡采样 |
| `--grad-checkpointing` | 关 | 梯度检查点，省显存 |
| `--seed` | 0 | 划分和采样的随机种子 |
| `--overwrite` | 关 | 清空已存在的 `--out` |

### 例子

```bash
# 用分析结果定位，LoRA，单卡 bf16
pip install -e '.[finetune]'
rba finetune --run runs/xxxx --out runs/xxxx/ft --dtype bfloat16 --device cuda --steps 200

# 手动指定层和模块，加额外训练数据
rba finetune --ft /models/ft --badcases bad.jsonl --goodcases control.jsonl \
  --layers 18,20 --modules o_proj,down_proj --extra-train more.jsonl --out runs/ft2

# 不装 peft：只训定位模块的全部权重
rba finetune --run runs/xxxx --mode full --lr 1e-5 --out runs/ft3

# 训练完再用 eval / analyze 检查新模型
rba analyze --base /models/ft --ft runs/xxxx/ft/model --badcases bad.jsonl --goodcases control.jsonl
```

### 显存与速度（2B，bf16，单卡）

- 只计算最后一个位置的 logits（`logits_to_keep=1`），不会为整段序列算 24 万词表的 logits；
- LoRA 适配器参数用 float32，基座权重保持 bf16、冻结；
- 显存紧张时：`--grad-checkpointing`、调小 `--train-batch-size`、调小配置里的 `max_length` / `image_max_pixels`。

### 限制

- 训练样本通常很少，修复率在训练坏例上会偏乐观，以留出坏例和留出对照的数字为准；样本少时 Wilson 区间很宽。
- 分析时没有留验收集的话，`--train-holdout` 留出的坏例参与过选层，不是完全独立的验收。
- full 模式直接在 bf16 权重上用 AdamW 更新，小学习率下可能更新不动或不稳定，优先用 LoRA。
- 内置小模型（tiny）只存 `model_state.pt`，仅供测试。
- 本仓库的测试在 CPU 上的随机小模型上跑通；真实 2B 单卡 bf16 的路径（logits_to_keep、bf16 基座 + fp32 适配器、梯度检查点）按 transformers 5.22 接口实现，但仓库 CI 没有 GPU。
- peft 是可选依赖：没装时 `--mode lora` 会提示安装方式，或改用 `--mode full`。
